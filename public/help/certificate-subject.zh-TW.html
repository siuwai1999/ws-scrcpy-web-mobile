認識 TLS 憑證:用簡單的方式解釋「主體名稱」

如果你曾在瀏覽器網址旁看過那個小小的鎖頭圖示,你就看過 TLS 憑證在運作。

TLS 憑證就像網路或私有網路上伺服器的數位身分證或護照。它確保兩件事:

  1. 隱私:你的電腦與伺服器之間的對話會被加密(內容被打亂,竊聽者無法讀取)。
  2. 身分驗證:你確實連到了你想連的那台電腦,而不是冒牌貨。

1. 什麼是「主體名稱」?

把 TLS 憑證想成政府核發的護照:

  • 護照上列有你的法定姓名,用來證明你是誰。
  • TLS 憑證列有主體名稱(或主體別名 / SAN),用來證明它屬於哪個伺服器位址。

當你的電腦連線到伺服器時,伺服器會出示它的憑證。你的電腦會檢查憑證上的主體名稱,並問:

「我在瀏覽器網址列輸入的名稱或位址,和這張身分證上正式蓋印的名稱相符嗎?」

  • 如果相符:連線會安全地進行(綠色鎖頭 / 安全標章)。前提是瀏覽器信任該憑證。請參閱下方的安裝憑證(建立信任)一節。
  • 如果不相符:瀏覽器會顯示警告,例如「你的連線不是私人連線」或「憑證名稱不符」。

2. 位址與名稱:現實世界的類比

想像寄信,就能理解連線如何運作:

概念現實世界類比電腦範例
IP 位址精確的 GPS 座標(北緯 37.7749°,西經 122.4194°)192.168.1.50 或 142.250.190.46
主機名稱建築物的暱稱(例如「總部」)mailserver 或 fileshare
FQDN(完整名稱)完整且唯一的郵寄地址(例如「美國德州奧斯汀主街 100 號」)mail.company.com

3. 連線如何運作(逐步說明)

情境 A:使用網域名稱(FQDN)連線

這是你造訪 https://bank.example.com 時發生的事。

  1. 你輸入名稱:你在網址列輸入 bank.example.com。
  2. 名稱解析(DNS):你的電腦不知道 bank.example.com 實際位在網路上的哪裡,所以向 DNS 伺服器(網際網路的通訊錄)詢問:

    「bank.example.com 的 IP 位址是什麼?」

    DNS 回覆:「在 203.0.113.10。」

  3. 連到伺服器:你的電腦聯絡位於 203.0.113.10 的電腦。
  4. 出示身分證:伺服器交出它的 TLS 憑證。
  5. 驗證檢查:你的電腦查看憑證的主體名稱。
    • 它看到:Subject: bank.example.com。
    • 你的電腦說:「我要的是 bank.example.com,而這張憑證寫的也是 bank.example.com。沒問題!」
    • 安全連線建立。

情境 B:使用簡短主機名稱連線(內部網路)

在辦公室或家用網路中,人們常用簡短的暱稱取代完整網域名稱(例如連到名為 backup-server 的印表機或內部伺服器)。

  1. 你輸入暱稱:你前往 https://backup-server。
  2. 本機名稱解析:你的辦公室路由器或本機目錄查詢名稱 backup-server,找到它的區域網路位址(例如 10.0.0.15)。
  3. 憑證檢查:
    • 如果憑證的主體名稱明確列出 backup-server,連線就會成功。
    • 常見問題:如果憑證只列出完整名稱(backup-server.local 或 backup-server.company.com),你的電腦會報錯,因為你輸入的簡短暱稱與憑證上印的內容不符。

情境 C:直接連到 IP 位址

有時技術管理員會直接連到 IP 位址(例如輸入 https://192.168.1.1 來開啟家用路由器的設定)。

  1. 不需查詢:因為你提供了精確的數字座標,你的電腦完全略過通訊錄(DNS),直接前往 192.168.1.1。
  2. 憑證檢查:伺服器交出憑證,你的電腦會在憑證的主體別名中尋找 IP 位址項目。
  3. 結果:
    • 如果憑證內嵌了 IP: 192.168.1.1:檢查通過。
    • 如果憑證只有網域名稱(例如 router.lan):你的電腦會警告不符,因為你輸入的是數字(192.168.1.1),但身分證只宣稱了文字名稱(router.lan)。

4. 安裝憑證(建立信任)

網址列中的名稱相符,只是身分檢查的一半。你的作業系統與瀏覽器還必須信任核發這張身分證的單位。

  • 公開憑證:當你造訪 Google 或銀行等網站時,它們的憑證是由知名、全球公認的憑證授權單位(CA)簽發。作業系統與瀏覽器已預先內建這些受信任的簽發者。
  • 私有 / 內部憑證:對於本機的家用實驗室、內部網路伺服器或私有設備,你會建立自己的憑證授權單位。由於你的裝置預設不認得這個新的授權單位,你必須在每台要連線的電腦上安裝一次根憑證。

ws-scrcpy-web 下載的憑證(設定 → Local HTTPS → 下載 CA 憑證)檔名為 ws-scrcpy-web-local-ca.crt。

請依照下列適用於你作業系統或瀏覽器的說明操作:

快速跳轉:Windows · macOS · Linux · Android · iOS / iPadOS · Firefox

Windows

  1. 按兩下下載的憑證檔(.crt)。
  2. 按一下安裝憑證...。
  3. 在存放位置下,選擇:
    • 本機電腦(建議):讓這台電腦上的所有帳號都信任此憑證(需要管理員確認)。
    • 目前使用者:只讓你目前登入的帳號信任此憑證。
  4. 按一下下一步,選擇將所有憑證放入以下的存放區,再按一下瀏覽...。
  5. 選擇受信任的根憑證授權單位,然後按一下確定。
  6. 按一下下一步,再按完成。如果出現安全性確認警告,請按是。
  7. 重新啟動你的瀏覽器。

macOS

  1. 開啟鑰匙圈存取(按 Cmd + Space,輸入 Keychain Access,再按 Enter)。
  2. 在左側欄中,選擇系統鑰匙圈。
  3. 將下載的憑證檔直接拖放到清單中。
  4. 按兩下新加入的憑證,開啟它的設定視窗。
  5. 展開信任區段。
  6. 將使用此憑證時設為永遠信任。
  7. 關閉視窗,並在提示時以管理員密碼或 Touch ID 驗證。
  8. 重新啟動 Safari 或你的瀏覽器。

Linux

Linux 透過背景的命令列工具管理系統憑證。GNOME 與 KDE 桌面環境,對於 Chromium 系瀏覽器、cURL 與系統工具,都依賴這些底層的系統憑證庫。

Ubuntu / Debian 系列(Ubuntu Desktop、Pop!_OS、Linux Mint)

  1. ws-scrcpy-web 下載的檔案已經以 .crt 結尾,正是這個資料夾所需要的。(從其他地方取得、以 .pem 或 .cer 結尾的憑證,必須先改名為 .crt 結尾。)
  2. 將檔案複製到系統 CA 資料夾: 
    sudo cp ws-scrcpy-web-local-ca.crt /usr/local/share/ca-certificates/
  3. 更新系統信任資料庫: 
    sudo update-ca-certificates

Fedora / RHEL 系列(Fedora Workstation、CentOS Stream、Rocky Linux)

  1. 將憑證檔複製到來源錨點資料夾: 
    sudo cp ws-scrcpy-web-local-ca.crt /etc/pki/ca-trust/source/anchors/
  2. 更新系統信任資料庫: 
    sudo update-ca-trust

(給 GNOME 與 KDE 桌面使用者的說明:雖然 GNOME 的「密碼與金鑰」或 KDE 的「Kleopatra」等工具會顯示金鑰,但執行上述指令能確保所有系統軟體與桌面瀏覽器立即採用信任。)

Android

  1. 將憑證檔下載到裝置上(或透過 USB / 區域網路分享傳輸)。
  2. 開啟設定 → 安全性與隱私權(或安全性)。
  3. 點選更多安全性設定 → 加密與憑證(或憑證)。
  4. 點選安裝憑證 → CA 憑證。
  5. 閱讀警告提示後點選仍要安裝,再以 PIN、指紋或圖形驗證你的身分。
  6. 在檔案選取器中選擇你下載的憑證檔。

iOS / iPadOS

Apple 要求必須完成兩個步驟:安裝與信任。

  1. 步驟 1:安裝描述檔
    • 在 Safari 中下載憑證,或透過 AirDrop 傳到你的裝置。
    • 出現下載設定描述檔的提示時,點選允許。
    • 開啟設定,畫面上方附近會出現已下載描述檔的提示(或前往設定 → 一般 → VPN 與裝置管理)。
    • 點選下載的描述檔,點選右上角的安裝,輸入裝置密碼並確認。
  2. 步驟 2:開啟完全信任
    • 前往設定 → 一般 → 關於本機。
    • 捲動到最底部,點選憑證信任設定。
    • 在針對根憑證啟用完全信任下,找到你的憑證,並將開關切換為開啟。
    • 點選繼續以確認提示。

使用 Mozilla Firefox?

與 Chrome、Edge 和 Safari(它們直接讀取 Windows、macOS 或 Linux 的系統憑證庫)不同,Mozilla Firefox 使用自己獨立的憑證資料庫:

  1. 開啟 Firefox 並前往設定(或在網址列輸入 about:preferences#privacy)。
  2. 點選左側欄的隱私權與安全性。
  3. 捲動到憑證區段,點選檢視憑證...。
  4. 在憑證管理員彈出視窗中,選擇憑證授權單位分頁。
  5. 點選底部的匯入...。
  6. 選擇你下載的憑證檔。
  7. 在開啟的提示中,勾選信任這個 CA 來識別網站。
  8. 點選確定,關閉設定,並重新整理你的目標網站。

5. 重點整理

  1. 相符原則:你在網址列輸入的任何內容,都必須出現在憑證的主體別名(SAN)清單中。
  2. DNS 找出位置;憑證證明身分:DNS 把好記的名稱轉換成 IP 位址,讓你的電腦能連到那台機器。憑證則證明該位址上的機器確實被授權代表那個名稱。
  3. 信任 + 相符 = 安全:兩個條件都必須滿足:位址必須與身分證上印的相符,且簽發它的根授權單位必須安裝在你裝置的信任庫中。
  4. IP 位址更難取得憑證:公開憑證授權單位很少為公開的 IP 位址簽發憑證,也從不為私有區域網路 IP(例如 192.168.x.x)簽發。私有 IP 的環境需要自行簽發憑證,並依第 4 節的步驟匯入。
