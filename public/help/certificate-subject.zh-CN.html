认识 TLS 证书:用简单的方式解释“主题名称”

如果你曾在浏览器网址旁看过那个小小的锁头图示,你就看过 TLS 证书在运作。

TLS 证书就像网络或私有网络上服务器的数位身份证或护照。它确保两件事:

  1. 隐私:你的计算机与服务器之间的对话会被加密(内容被打乱,窃听者无法读取)。
  2. 身份验证:你确实连到了你想连的那台计算机,而不是冒牌货。

1. 什么是“主题名称”?

把 TLS 证书想成政府核发的护照:

  • 护照上列有你的法定姓名,用来证明你是谁。
  • TLS 证书列有主题名称(或主题备用名称 / SAN),用来证明它属于哪个服务器地址。

当你的计算机连接到服务器时,服务器会出示它的证书。你的计算机会检查证书上的主题名称,并问:

“我在浏览器网址列输入的名称或地址,和这张身份证上正式盖印的名称匹配吗?”

  • 如果匹配:连接会安全地进行(绿色锁头 / 安全标章)。前提是浏览器信任该证书。请参阅下方的安装证书(建立信任)一节。
  • 如果不匹配:浏览器会显示警告,例如“你的连接不是私人连接”或“证书名称不匹配”。

2. 地址与名称:现实世界的类比

想像寄信,就能理解连接如何运作:

概念现实世界类比计算机范例
IP 地址精确的 GPS 座标(北纬 37.7749°,西经 122.4194°)192.168.1.50 或 142.250.190.46
主机名建筑物的昵称(例如“总部”)mailserver 或 fileshare
FQDN(完整名称)完整且唯一的邮寄地址(例如“美国德州奥斯汀主街 100 号”)mail.company.com
DNS(名称解析)电话簿或手机通讯录将 google.com 转换为 142.250.190.46

3. 连接如何运作(逐步说明)

情境 A:使用网域名称(FQDN)连接

这是你造访 https://bank.example.com 时发生的事。

  1. 你输入名称:你在网址列输入 bank.example.com。
  2. 名称解析(DNS):你的计算机不知道 bank.example.com 实际位在网络上的哪里,所以向 DNS 服务器(互联网的通讯录)询问:

    “bank.example.com 的 IP 地址是什么?”

    DNS 回覆:“在 203.0.113.10。”

  3. 连到服务器:你的计算机联络位于 203.0.113.10 的计算机。
  4. 出示身份证:服务器交出它的 TLS 证书。
  5. 验证检查:你的计算机查看证书的主题名称。
    • 它看到:Subject: bank.example.com。
    • 你的计算机说:“我要的是 bank.example.com,而这张证书写的也是 bank.example.com。没问题!”
    • 安全连接建立。

情境 B:使用简短主机名连接(内部网络)

在办公室或家用网络中,人们常用简短的昵称取代完整网域名称(例如连到名为 backup-server 的印表机或内部服务器)。

  1. 你输入昵称:你前往 https://backup-server。
  2. 本机名称解析:你的办公室路由器或本机目录查询名称 backup-server,找到它的局域网地址(例如 10.0.0.15)。
  3. 证书检查:
    • 如果证书的主题名称明确列出 backup-server,连接就会成功。
    • 常见问题:如果证书只列出完整名称(backup-server.local 或 backup-server.company.com),你的计算机会报错,因为你输入的简短昵称与证书上印的内容不匹配。

情境 C:直接连到 IP 地址

有时技术管理员会直接连到 IP 地址(例如输入 https://192.168.1.1 来打开家用路由器的设置)。

  1. 不需查询:因为你提供了精确的数字座标,你的计算机完全略过通讯录(DNS),直接前往 192.168.1.1。
  2. 证书检查:服务器交出证书,你的计算机会在证书的主题备用名称中寻找 IP 地址项目。
  3. 结果:
    • 如果证书内嵌了 IP: 192.168.1.1:检查通过。
    • 如果证书只有网域名称(例如 router.lan):你的计算机会警告不匹配,因为你输入的是数字(192.168.1.1),但身份证只宣称了文字名称(router.lan)。

4. 安装证书(建立信任)

网址列中的名称匹配,只是身份检查的一半。你的作业系统与浏览器还必须信任核发这张身份证的单位。

  • 公开证书:当你造访 Google 或银行等网站时,它们的证书是由知名、全球公认的证书颁发机构(CA)签发。作业系统与浏览器已预先内建这些受信任的签发者。
  • 私有 / 内部证书:对于本机的家用实验室、内部网络服务器或私有设备,你会建立自己的证书颁发机构。由于你的设备默认不认得这个新的授权单位,你必须在每台要连接的计算机上安装一次根证书。

ws-scrcpy-web 下载的证书(设置 → Local HTTPS → 下载 CA 证书)文件名为 ws-scrcpy-web-local-ca.crt。

请依照下列适用于你作业系统或浏览器的说明操作:

快速跳转:Windows · macOS · Linux · Android · iOS / iPadOS · Firefox

Windows

  1. 按两下下载的证书文件(.crt)。
  2. 点击安装证书...。
  3. 在存放位置下,选择:
    • 本机计算机(建议):让这台计算机上的所有账号都信任此证书(需要管理员确认)。
    • 目前用户:只让你目前登录的账号信任此证书。
  4. 点击下一步,选择将所有证书放入以下的存放区,再点击浏览...。
  5. 选择受信任的根证书颁发机构,然后点击确定。
  6. 点击下一步,再按完成。如果出现安全性确认警告,请按是。
  7. 重启你的浏览器。

macOS

  1. 打开钥匙串访问(按 Cmd + Space,输入 Keychain Access,再按 Enter)。
  2. 在左侧栏中,选择系统钥匙串。
  3. 将下载的证书文件直接拖放到清单中。
  4. 按两下新加入的证书,打开它的设置窗口。
  5. 展开信任区段。
  6. 将使用此证书时设为永远信任。
  7. 关闭窗口,并在提示时以管理员密码或 Touch ID 验证。
  8. 重启 Safari 或你的浏览器。

Linux

Linux 透过背景的命令列工具管理系统证书。GNOME 与 KDE 桌面环境,对于 Chromium 系浏览器、cURL 与系统工具,都依赖这些底层的系统证书库。

Ubuntu / Debian 系列(Ubuntu Desktop、Pop!_OS、Linux Mint)

  1. ws-scrcpy-web 下载的文件已经以 .crt 结尾,正是这个文件夹所需要的。(从其他地方取得、以 .pem 或 .cer 结尾的证书,必须先改名为 .crt 结尾。)
  2. 将文件复制到系统 CA 文件夹: 
    sudo cp ws-scrcpy-web-local-ca.crt /usr/local/share/ca-certificates/
  3. 更新系统信任数据库: 
    sudo update-ca-certificates

Fedora / RHEL 系列(Fedora Workstation、CentOS Stream、Rocky Linux)

  1. 将证书文件复制到来源锚点文件夹: 
    sudo cp ws-scrcpy-web-local-ca.crt /etc/pki/ca-trust/source/anchors/
  2. 更新系统信任数据库: 
    sudo update-ca-trust

(给 GNOME 与 KDE 桌面用户的说明:虽然 GNOME 的“密码与金钥”或 KDE 的“Kleopatra”等工具会显示金钥,但运行上述指令能确保所有系统软件与桌面浏览器立即采用信任。)

Android

  1. 将证书文件下载到设备上(或透过 USB / 局域网分享传输)。
  2. 打开设置 → 安全性与隐私(或安全性)。
  3. 点按更多安全性设置 → 加密与证书(或证书)。
  4. 点按安装证书 → CA 证书。
  5. 阅读警告提示后点按仍要安装,再以 PIN、指纹或图形验证你的身份。
  6. 在文件选取器中选择你下载的证书文件。

iOS / iPadOS

Apple 要求必须完成两个步骤:安装与信任。

  1. 步骤 1:安装描述文件
    • 在 Safari 中下载证书,或透过 AirDrop 传到你的设备。
    • 出现下载设置描述文件的提示时,点按允许。
    • 打开设置,画面上方附近会出现已下载描述文件的提示(或前往设置 → 一般 → VPN 与设备管理)。
    • 点按下载的描述文件,点按右上角的安装,输入设备密码并确认。
  2. 步骤 2:打开完全信任
    • 前往设置 → 一般 → 关于本机。
    • 卷动到最底部,点按证书信任设置。
    • 在针对根证书启用完全信任下,找到你的证书,并将开关切换为打开。
    • 点按继续以确认提示。

使用 Mozilla Firefox?

与 Chrome、Edge 和 Safari(它们直接读取 Windows、macOS 或 Linux 的系统证书库)不同,Mozilla Firefox 使用自己独立的证书数据库:

  1. 打开 Firefox 并前往设置(或在网址列输入 about:preferences#privacy)。
  2. 点按左侧栏的隐私与安全性。
  3. 卷动到证书区段,点按检视证书...。
  4. 在证书管理员弹出窗口中,选择证书颁发机构标签页。
  5. 点按底部的汇入...。
  6. 选择你下载的证书文件。
  7. 在打开的提示中,勾选信任这个 CA 来识别网站。
  8. 点按确定,关闭设置,并刷新你的目标网站。

5. 重点整理

  1. 匹配原则:你在网址列输入的任何内容,都必须出现在证书的主题备用名称(SAN)清单中。
  2. DNS 找出位置;证书证明身份:DNS 把好记的名称转换成 IP 地址,让你的计算机能连到那台机器。证书则证明该地址上的机器确实被授权代表那个名称。
  3. 信任 + 匹配 = 安全:两个条件都必须满足:地址必须与身份证上印的匹配,且签发它的根授权单位必须安装在你设备的信任库中。
  4. IP 地址更难取得证书:公开证书颁发机构很少为公开的 IP 地址签发证书,也从不为私有局域网 IP(例如 192.168.x.x)签发。私有 IP 的环境需要自行签发证书,并依第 4 节的步骤汇入。
